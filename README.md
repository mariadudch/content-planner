# Контент-планер для блога — проект курса Python

Индивидуальный проект «Автоматизируй свою рутину». Рутина — разложить идеи для блога
по рубрикам и форматам и собрать из них контент-план.

**Как было раньше:** идеи копились в заметках и голосовых, раз в неделю я вручную решала,
что из идеи можно сделать (рилс, карусель, пост в Телеграм, сторис, влог), к какой рубрике
она относится, и расставляла всё по дням так, чтобы темы не повторялись подряд.

**Как стало:** пишу идеи текстом в один файл, по строке на идею. Программа по словам-сигналам
находит рубрики (одна мысль может попасть в несколько), берёт все форматы, которые подходят
этим рубрикам, и ставит получившиеся единицы контента в план. Идея без рубрики идёт в сторис
и пост в Telegram. Все правила лежат в `rules.json`.

## Структура

- [main.py](main.py) — команды программы (`run`, `add`, `show`, `preview`).
- [models.py](models.py) — классы данных: идея и единица контента.
- [reader.py](reader.py) — чтение файла с идеями и чистка грязных строк.
- [classifier.py](classifier.py) — рубрики и форматы: по словам-сигналам превращает идею в единицы контента.
- [storage.py](storage.py) — память программы: контент-план (`ContentPlan`), сохранение в `data/state.json`, очистка файла с идеями.
- [planner.py](planner.py) — расстановка единиц контента по датам с учётом лимитов и чередования тем.
- [export.py](export.py) — строки таблицы и выгрузка плана в CSV.
- [sheets.py](sheets.py) — отправка плана на отдельный лист Google Таблицы.
- [rules.json](rules.json) — мои правила: рубрики, слова-сигналы, форматы, площадки, лимиты и горизонт плана.
- [examples/](examples/) — выдуманные идеи для демонстрации и пример настроек Google Таблицы.
- [tests/](tests/) — тесты.
- `data/` — мои настоящие идеи (`ideas.txt`), память программы (`state.json`), план-таблица (`plan.csv`),
  настройки и ключ Google (`google.json`, `google_key.json`). В репозиторий не попадает (личные данные и секреты).

## Запуск

Один раз — создать окружение и поставить зависимости:

```
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Дальше (каждый раз в новом терминале сначала `source .venv/bin/activate`):

## Команды

| Команда | Что делает |
|---|---|
| `python main.py run` | Разбирает `data/ideas.txt`, ставит даты, сохраняет память (`data/state.json`) и таблицу (`data/plan.csv`), очищает разобранные строки |
| `python main.py add "Нашла классный тинт"` | Добавляет одну идею прямо из терминала — разбор, дата, сохранение |
| `python main.py show` | Показывает план из памяти начиная с сегодня, ничего не меняет. `--days 7` — только неделя |
| `python main.py preview examples/ideas_demo.txt` | Разбор и план для любого файла на пустой памяти, ничего не сохраняет (для демо) |
| `python main.py sync` | Отправляет план из памяти в Google Таблицу (`run` и `add` делают это сами) |
| `python main.py --help` | Список команд |

`data/ideas.txt` работает как «входящие»: после `run` в нём остаются только строки, которые
нужно поправить. Сначала сохраняется память, и только потом чистится файл: если программа
оборвётся между этими шагами, идея не потеряется (в худшем случае повторится).

`data/plan.csv` открывается в Excel и Google Таблицах: дата, день недели, формат, площадки,
рубрика, идея. Сначала — по датам, в конце — бэклог (без даты).

## Google Таблица

После `run` и `add` план отправляется на **отдельный лист** моей Google Таблицы (по умолчанию
«План от программы»): те же колонки, что в CSV. Лист каждый раз перезаписывается целиком —
это витрина, главная память остаётся в `data/state.json`. Другие листы (календарная сетка) не трогаются.
Если листа нет — программа его создаёт.

Настройка (один раз):
1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект.
2. «APIs & Services» → «Library» → **Google Sheets API** → Enable.
3. «IAM & Admin» → «Service Accounts» → Create service account (роли не нужны).
4. В сервисном аккаунте: «Keys» → «Add key» → «Create new key» → JSON. Скачанный файл
   переименовать в `google_key.json` и положить в `data/`. **Это секрет**: в репозиторий он не попадает
   (`data/` и `google_key.json` в `.gitignore`).
5. Скопировать почту сервисного аккаунта (`...@...iam.gserviceaccount.com`) и в Google Таблице:
   «Настройки доступа» → добавить эту почту как **редактора**.
6. Скопировать [examples/google.example.json](examples/google.example.json) в `data/google.json`
   и вставить ссылку на свою таблицу.
7. `pip install -r requirements.txt` (библиотека `gspread`), затем `python main.py sync`.

Без настройки программа работает как раньше (CSV) и просто пишет «Google Таблица не настроена».

## Повторы идей

Для блога нормально возвращаться к одной теме много раз. Если идея уже есть в памяти,
она снова идёт в план с пометкой «часть 2», «часть 3» и т. д. Первый раз — без пометки.
«Та же идея» — тот же текст без учёта регистра, пунктуации и «ё»/«е».

## Формат файла с идеями

- одна идея — одна строка;
- `!` в начале строки — срочная идея;
- хештеги особого смысла не имеют: `#уход` для программы — просто слово «уход»;
- маркеры списка `- `, `• `, `1. `, `2) ` можно оставлять.

## Грязные данные и краевые случаи

| Случай | Что делает программа |
|---|---|
| Пустые строки | Пропускает молча, но номера строк в сообщениях остаются настоящими |
| Разделители `---`, строки из одних эмодзи `✨✨✨` | Пропускает молча |
| Маркеры списка из заметок (`- `, `• `, `1. `, `2) `) | Убирает. Число без точки («15 минут…») маркером не считает |
| Идея из одного слова («крем») | Пропускает с предупреждением «допиши мысль» и оставляет строку в файле, чтобы её дописать |
| Повтор идеи с другим регистром, пунктуацией, «е» вместо «ё» | Считает той же идеей: следующая «часть» |
| Одна и та же идея дважды в одном файле | Вторая — «часть 2» (к этому моменту первая уже в памяти) |
| Файл сохранён в Windows-1251 | Читает |
| Файл в UTF-8 с BOM (невидимый символ в начале) | Читает, BOM не попадает в текст |
| Файла нет / указана папка | Понятное сообщение, без падения |
| Файл сохранён в TextEdit как RTF (`ideas.rtf`, начинается с `{\rtf`) | Не принимает служебные строки RTF за идеи и не чистит файл: просит сохранить обычным текстом. Нашла на своих данных |
| Ошибка в `rules.json` (пропущена запятая, кавычка) | Сообщает номер строки в `rules.json`, не падает |
| Опечатка в названии формата в `rules.json` («Рилз») | Сообщает, у какой рубрики и какой формат не найден |
| Пустое слово-сигнал в `rules.json` («!!!») | Сообщает, иначе такое «слово» совпадало бы с любой идеей |
| Сигнал внутри другого слова: «сбор» в «разбор» | Не срабатывает: сигнал — это начало слова |
| Сигнал случайно включал окончание: `спрей` не находил «спре**я**» («тест разглаживающего спрея» ушёл в «Без рубрики») | Нашла на своих данных в Google Таблице. Исправила правила: сигнал — основа без окончания (`спре`, `гел`, `кист`, `туш`, `бров`, `тревож`, `достойн`...) |
| Короткий сигнал: «вб» и «вбить», «с» и «спортивная» | Сигналы из 1–2 букв сравниваются со словом целиком |
| Фраза «больш низ», но слова далеко или в другом порядке | Не срабатывает: фраза ищется как слова подряд |
| «ё» в `rules.json` | Работает так же, как «е» |
| Ни одна рубрика не подошла («Купила новую кружку») | Идея идёт в сторис и пост в Telegram с пометкой «Без рубрики» |
| Первый запуск — памяти ещё нет | Начинает с пустого плана |
| Файл памяти повреждён (обрыв записи, правка руками) | Не падает: переименовывает его в `state.broken.json` (ничего не теряется), предупреждает и начинает с пустого плана |
| Программа оборвалась во время записи памяти | Запись идёт во временный файл, который потом одним действием заменяет старый — старая память не испортится |
| Запуск на демо-файле из репозитория (`preview`) | Файл не очищается, память не меняется |
| `run`, а файла `data/ideas.txt` нет | Не падает: новых идей нет, план обновляется (бэклог получает даты) |
| `add "крем"` — слишком короткая идея | Сообщает и ничего не сохраняет |
| Запуск без команды или с неизвестной командой | argparse показывает подсказку по командам |
| `show --days 0` или `--days неделя` | Сообщает, что нужно целое число от 1 |
| CSV открывают в русском Excel | Разделитель `;` и метка кодировки (BOM): колонки и русские буквы не ломаются |
| В тексте идеи есть `;` | Модуль csv берёт ячейку в кавычки — колонка не разрезается |
| Идея начинается с `=`, `+`, `-`, `@` («=) смешной рилс») | Перед ней ставится апостроф, иначе таблица приняла бы её за формулу |
| Google Таблица не настроена (нет `data/google.json`) | Работает как раньше: CSV, без отправки, с подсказкой |
| Нет ключа `google_key.json` / ключ испорчен / скачан не тот файл | Понятное сообщение, план сохранён в `state.json` и CSV |
| Таблицей не поделились с сервисным аккаунтом | Сообщает, **какую почту** добавить в доступ |
| Неправильная ссылка в `google.json` | Сообщает, что ссылка не похожа на Google Таблицу |
| Нет интернета | Не падает: «проверь интернет», план уже сохранён локально |
| Не установлена библиотека `gspread` | Подсказывает `pip install -r requirements.txt`; остальная программа работает |
| Листа «План от программы» ещё нет | Создаёт его; другие листы не трогает |
| План длиннее, чем строк на листе | Добавляет строки на лист перед записью |
| В плане уже стоят единицы в прошлые дни этой недели | Они учитываются в недельном лимите: если рилсов на неделе уже 5, новый ждёт понедельника |
| Единице не хватило места в горизонте | Остаётся в бэклоге, при следующем запуске пробует снова |
| Память сохранена до этапа 4 (у единиц нет дат) | Читается без ошибок: такие единицы считаются бэклогом и получают даты |
| Формат переименован или удалён из `rules.json`, а в памяти он есть | Не падает: единица остаётся в бэклоге, программа пишет, какого формата не хватает |
| Лимит в `rules.json` записан как `0`, `"5"` (в кавычках), `2.5`, `true` | Сообщает, у какого формата и какой лимит неправильный |
| Поменяла `rules.json` после того, как идеи уже в плане | Старые идеи сохраняют прежние рубрики (у них будут даты в плане), новые правила — только для новых идей |

## Как программа выбирает рубрики и форматы

1. Для каждой рубрики считает, сколько её слов-сигналов нашлось в идее.
2. Подходит каждая рубрика, где нашлось хотя бы одно слово (`MIN_MATCHES` в `classifier.py`).
3. Каждая пара «подошедшая рубрика + её формат» становится отдельной единицей контента:
   из одной мысли — максимум контента. Площадки берутся из раздела `formats`.

## Как программа ставит даты

Жадный алгоритм: единицы контента берутся по очереди (сначала срочные `!`, потом в порядке
добавления), и каждая ставится на **ближайший** день, начиная с завтрашнего, где соблюдены все правила:

1. **Лимиты формата** (в `rules.json`, раздел `formats`):

   | Формат | Лимит |
   |---|---|
   | Рилс | 5 в неделю, 1 в день |
   | Пост в Telegram | 21 в неделю, 3 в день |
   | Пост-карусель | 3 в неделю, 1 в день |
   | Влог | 2 в месяц, 1 в день |
   | Сторис | 2 в день |

   Неделя — с понедельника по воскресенье, месяц — календарный.
2. **Чередование тем:** один и тот же формат с одной рубрикой — не два дня подряд.
3. **Единицы одной идеи** — не в один день (части 2, 3 — это разные идеи).

План строится на `horizon_days` дней вперёд (сейчас 28). Что не влезло — в **бэклоге**:
при следующих запусках эти единицы займут освободившиеся дни. Уже назначенные даты не двигаются.

## Известные ограничения

Сигнал должен быть **основой слова без окончания**, иначе часть форм не найдётся (случай со «спреем»).
Программа этого не проверяет — это правило для того, кто пишет `rules.json`.

Сравнение по началу слова не понимает смысла. Найденные на демо-данных ложные срабатывания:
- «идеальный бежевый тренч» → «Мысли о красоте» (сигнал `идеальн`);
- «собрала капсулу» → «Моя рутина: сборы со мной» (сигнал `собрал`);
- «краситься каждый день» → «Находки одежды» (фраза `кажд ден`).

Лишние единицы контента не страшны: план и так фильтрует их лимитами. Исправляется правкой
слов в `rules.json`. Полное решение — морфологический анализ или нейросеть, но тогда логику
сложнее объяснить и проверить.
